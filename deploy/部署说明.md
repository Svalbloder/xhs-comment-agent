# 客户机部署说明（Windows）

这个文档是给**实施/交付同学**看的：在一台干净电脑上把这个产品装起来，跑通，交给客户。

---

## 一、前提

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11，x64 |
| DSH | 桌面端已安装，并且**至少启动过一次**（要它生成 `%USERPROFILE%\.dsh\profiles\...`） |
| 账号 | 一个能正常登录的小红书账号（建议先实名，新号容易被要求验证） |
| 网络 | 能访问 GitHub 镜像（安装器默认走 `ghfast.top`，失败会自动换） |
| 权限 | 安装过程需要管理员（仅用于 Defender 排除；不加也能装，见故障排查） |

> 不需要装 Node、Python、Docker。插件跑在 DSH 宿主进程里。

---

## 二、分发物

把整个 `xhs-comment-agent` 文件夹打包发给客户/实施同学，结构如下：

```
xhs-comment-agent\
├─ deploy\
│   ├─ install.ps1          ← 安装器
│   ├─ uninstall.ps1        ← 卸载器
│   └─ 部署说明.md          ← 本文件
├─ bundle\src\              ← 插件源码（install 会复制到 ~/.dsh/plugins）
│   ├─ index.js             ← 宿主插件：工具 + 进程托管 + 风控
│   ├─ panel.js/.html       ← 本地控制台
│   ├─ xlsx.js              ← 零依赖 xlsx 解析
│   └─ mapping.js           ← Excel → rules.json 映射
└─ 交付物\
    ├─ 小红书评论Agent-客户配置清单.xlsx        ← 给客户填
    └─ ...（已填样例）.xlsx                     ← 演示/回归用
```

## 三、安装（一条命令）

在**管理员** PowerShell 里：

```powershell
cd <解压目录>\xhs-comment-agent
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\install.ps1
```

安装器做四件事：

1. 复制插件到 `%USERPROFILE%\.dsh\plugins\xhs-comment-agent`
2. 下载 `xiaohongshu-mcp.exe` / `xiaohongshu-login.exe` 到 `%USERPROFILE%\.dsh\runtimes`
3. 在 `%USERPROFILE%\.dsh\profiles\<desktop>\cordis.patch.yml` 里登记插件（**幂等**，重复执行只会覆盖同一行）
4. 给 Defender 加两个排除目录（`runtimes` 和 `%LOCALAPPDATA%\xiaohongshu-mcp`）

常用参数：

| 参数 | 用途 |
|---|---|
| `-Preview` | 只检查 + 打印，不写任何文件。**第一次装建议先跑这个** |
| `-SkipDownload` | 二进制已经拷好时跳过下载（离线交付） |
| `-SkipDefender` | 不动杀软设置 |
| `-RunLogin` | 装完直接弹扫码窗口 |

## 四、首次登录（只做一次）

```powershell
cd "$env:USERPROFILE\.dsh\xhs-agent"
& "$env:USERPROFILE\.dsh\runtimes\xiaohongshu-login.exe"
```

会弹出一个 Chromium 窗口，用手机小红书扫码。成功后 cookies 落在
`%USERPROFILE%\.dsh\xhs-agent\cookies.json`。

> **必须在这个目录下运行登录**。xiaohongshu-mcp 是从「当前工作目录」读 cookies 的，
> 换个目录启动服务，登录态会直接消失（实测 `is_logged_in: false`）。

> 同一账号**不要**在多个网页端同时登录，否则会把这边踢下线。

---

## 五、重启 DSH

托盘图标右键 → 退出（不是关窗口），再打开。

插件只在 DSH 启动时装配，不重启不会生效。

## 六、验证清单

按顺序过，每步过了再走下一步：

| # | 动作 | 期望 |
|---|---|---|
| 1 | 打开 `http://127.0.0.1:18765/` | 页面出来，状态条显示「服务在线」 |
| 2 | 看状态条右侧 | 「已登录 · <你的昵称>」 |
| 3 | 面板「导入客户配置清单」选客户填的 xlsx → 解析预览 | 显示客户名/关键词/配额，缺必填会被标红 |
| 4 | 点「应用到系统」 | 提示已应用，表单同步刷新 |
| 5 | 对话里让 Agent 搜一个关键词 | 返回笔记列表（带 feedId / xsecToken） |
| 6 | 让它抓某篇笔记的评论 | 返回一级/二级评论候选 |
| 7 | 让它“做成草稿” | 面板「待审草稿」出现条目 |
| 8 | 保持干跑，点「发送这条」 | 被拒绝（`dry_run_on`）——这是对的 |
| 9 | 关掉干跑 → 保存 → 发送一条 | 小红书网页上能看到回复挂在目标评论下 |

## 七、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板打不开 | DSH 没重启 / 端口 18765 被占 | 先重启 DSH；`Get-NetTCPConnection -LocalPort 18765` 看占用 |
| 面板「服务离线」 | 18060 被占，或 exe 被删 | `Get-NetTCPConnection -LocalPort 18060`；检查 `~/.dsh/runtimes` 两个 exe 是否在 |
| 登录窗口一开就闪退，日志里有 `fork/exec ... leakless.exe ... virus` | Defender 把 rod 的进程守护当病毒 | 加排除：`Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\xiaohongshu-mcp"` 和 `%TEMP%\leakless-amd64-*` 所在目录 |
| 登录成功但很快变未登录 | 服务的工作目录不是 `~/.dsh/xhs-agent` | 不要手动在别的目录起服务；插件配置里的 `cwd` 已钉死 |
| 搜索一直 0 条 | 登录态失效 / 关键词太窄 / 笔记筛选太严 | 先看面板登录状态；把 `min_liked`、`title_must_any` 放宽 |
| 评论 0 个候选 | `must_any` 太严 | 暂时清空 `must_any`，干跑看全量，再逐步收紧 |
| 发送被拒 `daily_quota` / `cooldown` / `already_sent` | 风控生效 | 正常行为，等或用面板换一条 |
| 发送被拒 `dry_run_on` | 干跑还开着 | 面板取消勾选「干跑」并保存 |
| DSH 起不来 | patch YAML 被改坏 | 用 `cordis.patch.yml.bak-<时间>` 覆盖回去（安装器每次都备份） |
| 报 `0xC0000142` | DSH 自己的 pwsh 沙箱问题，**与本插件无关** | 插件在宿主进程内 spawn，不走沙箱；这条错误只影响对话里的命令执行 |

## 八、升级

直接重跑安装器（幂等）：会覆盖插件代码、重写同一行配置、重新备份 YAML。
升级不碰 `~/.dsh/xhs-agent` 下的规则、草稿、去重记录。

升级完同样需要重启 DSH。

---

## 九、卸载

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\uninstall.ps1          # 保留数据
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\uninstall.ps1 -Purge   # 连数据一起删
```

卸载后重启 DSH。

## 十、安全与合规

- 面板只监听 `127.0.0.1:18765`，**没有鉴权**，不要做端口转发、不要暴露到公网。
- `cookies.json` 是明文登录态，等同账号密码，不要打包发给别人。
- 自动回复属于平台敏感行为：默认干跑、有小时/天配额、有去重和熔断，不要为了跑量把这些关掉。
- 建议先在自己笔记下试回复，再放到别人笔记；回复内容不要导流、不要报价。
